# 自动跳过功能设计文档

## 1. 目标

允许用户在播放页为当前音频记录一个或多个需要跳过的时间段。播放到该时间段时，播放器自动将进度跳到时间段结束位置。

自动跳过记录以音频路径（当前项目中的规范化 `AudioItem.key`，实际为音频 `content://` URI）区分音频，不使用标题或文件夹名作为唯一标识。同一个音频可以拥有多个记录。

除本文档中的手动标记外，已补充目录级开头/结尾规则，具体实现以当前代码为准。

## 2. 现有代码对接点

- 播放页是 `PlayerScreen`，底部操作区目前包含“播放模式、定时、跳过标记”三个按钮。
- “播放模式”按钮打开菜单，菜单中包含循环方式和“播放列表”；“播放列表”继续打开 `AppDialog.Queue` 队列小窗。
- 设置页是当前产品中的“设计页”入口，媒体库已经采用 `AppScreen.LIBRARY_SETTINGS` 这种二级页面模式。
- 播放由 `PlaybackService` 中的 `PlaybackCoordinator` 管理，播放位置约每 500ms 发布一次。
- 音频扫描完成后，`LibraryRepository` 会用当前扫描结果替换对应文件夹的旧音频列表，因此这里是清理失效标记的合适时机。
- 现有媒体库和播放快照分别持久化，自动跳过记录建议使用独立文件，避免改变音频缓存格式。

## 3. 数据模型

新增 `AutoSkipSegment`：

```text
id                  String      UUID，单条记录唯一标识
audioKey            String      音频规范化 URI，作为音频身份
audioUri            String      播放时使用的 URI 字符串
titleSnapshot       String      创建时的音频标题，用于展示兜底
folderNameSnapshot  String      创建时的文件夹名，用于展示兜底
relativePath        String      创建时的相对目录，用于展示和区分同名音频
startMs             Long        跳过开始位置，包含
endMs               Long        跳过结束位置，不包含
modifiedAtMs        Long        最后修改时间戳，管理页排序依据；首次创建时写入
```

约束：

- `startMs >= 0`、`endMs > startMs`。
- `audioKey` 必须来自当前 `AudioItem.key`；同一音频的多条记录只通过 `id` 区分。
- 记录完成时以当前播放位置为结束点，保存前将起止位置限制在当前音频时长内。
- 创建记录时保留标题和相对路径快照，但自动跳过和删除判断永远使用 `audioKey`。

持久化新增 `auto_skip_segments.json`，建议带 `version` 字段，结构类似：

```json
{
  "version": 1,
  "segments": [
    {
      "id": "...",
      "audioKey": "content://...",
      "audioUri": "content://...",
      "titleSnapshot": "片段标题",
      "folderNameSnapshot": "音乐",
      "relativePath": "专辑",
      "startMs": 30000,
      "endMs": 45000,
      "modifiedAtMs": 1777600000000
    }
  ]
}
```

新增 `AutoSkipRepository`，职责为：加载/保存记录、暴露 `StateFlow<List<AutoSkipSegment>>`、新增记录、按 ID 删除记录、按音频路径清理记录。

## 4. 播放页交互

### 4.1 操作按钮

将 `PlayerScreen` 操作区右侧的“列表”按钮替换为“跳过标记”按钮：

- 无当前音频时：按钮不可用。
- 初始状态：图标使用书签/标记类图标，文字为“跳过标记”。
- 第一次点击：记录当前音频和当前播放位置，按钮进入激活样式，文字变为“结束标记”。
- 第二次点击：读取当前播放位置，完成一条记录并恢复初始状态。
- 完成后不改变播放状态、不跳转进度。
- 记录成功后可用 Snackbar 或 Toast 提示区间，例如“已标记 0:30–0:45”。提示属于增强项，不影响核心逻辑。

### 4.2 未完成记录

未完成的起点只存在内存中，不写入磁盘。建议由 `AppViewModel` 持有：

```text
ActiveMark(audioKey, startMs)
```

以下情况自动取消未完成记录并恢复按钮：

- 当前播放音频发生变化；
- 播放页离开或 ViewModel 销毁；
- 结束点击时已没有当前音频。

如果结束位置小于或等于开始位置，不保存记录，并保持“结束标记”状态，让用户先把播放位置向后移动。这样可以避免产生零长度记录。

播放位置来自 `PlaybackCoordinator` 的最新状态；由于现有状态更新周期约为 500ms，记录精度为当前播放器状态的精度。若后续需要更精确，可再增加一次主线程即时读取位置的接口。

### 4.3 跨曲和手动拖动

- 标记的起点和终点必须属于同一个 `audioKey`，不能跨曲生成记录。
- 用户可以暂停后调整进度，再点击“结束标记”；暂停位置同样可作为起点或终点。
- 用户手动拖入已经标记的区间时，播放逻辑仍按自动跳过规则处理；不增加“本次播放已跳过”的持久状态。

## 5. 自动跳过播放逻辑

在 `PlaybackCoordinator` 中增加自动跳过检查，使用 `AutoSkipRepository.state.value` 查询当前音频的记录。

建议判定规则：

```text
当前 audioKey 匹配
且 positionMs >= startMs
且 positionMs < endMs
=> seekTo(endMs)
```

接入点：

1. 播放位置 tick 中检查，复用现有约 500ms 的位置更新机制。
2. 音频 prepared 后、恢复播放前检查一次，避免用户暂停在区间内后点击播放时漏跳。
3. 手动 `SeekTo` 后在下一次播放/位置检查中生效。

实现细节：

- 同一音频的区间按开始位置排序查找。
- 如果多个区间重叠或相邻，建议在查询层合并为区间并集，避免先跳到一个区间结束点后又落入下一个区间。
- 如果音频当前时长变短，运行时将 `endMs` 限制到当前时长；若限制后 `endMs <= startMs`，该记录本次忽略，不修改原始记录。
- 自动跳过使用 `seekTo`，不改变单音频播放状态和定时器状态。
- tick 检查应只处理当前 `audioKey`，避免异步加载旧音频时误跳。

## 6. 设置页和管理二级页

### 6.0 目录级跳过开头/结尾

播放页“菜单”中增加“跳过开头/结尾”入口。点击后弹出输入小窗，分别输入开头和结尾需要跳过的秒数；两项互相独立，输入 0 表示关闭对应规则。确认后只保存一条以 `folderUri + relativePath` 为键的目录规则，播放该目录下任意音频时动态应用，不生成普通 `AutoSkipSegment`，也不显示在设置页的自动跳过管理列表中。

目录规则单独持久化到 `directory_skip_rules.json`。规则修改时覆盖同一目录的旧规则，移除音乐库文件夹时同步删除该文件夹下的目录规则。

### 6.1 设置页入口

在设置页增加“自动跳过”分组，加入一行“自动跳过管理”：

- 有记录时显示“`N` 个时间段”；
- 无记录时显示“暂无标记”；
- 点击进入 `AppScreen.AUTO_SKIP_SETTINGS`。

该页面和现有媒体库二级页一样，脱离主 `HorizontalPager`，提供顶部返回按钮，不显示设置页底部播放控制条。

### 6.2 自动跳过管理页

新增 `AutoSkipScreen`，内容为可滚动列表。

每条记录显示：

- 音频标题；
- 音频相对路径/文件夹名，避免同名音频难以区分；
- 时间段：`startMs`–`endMs`，复用现有 `formatTime`；
- 可点击的播放按钮；
- 删除按钮。

列表排序：按 `modifiedAtMs` 降序，最后修改时间最新的标记排在最前；时间相同则按 `id` 做稳定排序。当前版本不提供编辑操作，因此新建记录时的时间同时作为其最后修改时间。

管理规则：

- 只允许播放和删除，不提供编辑入口。
- 删除建议使用确认对话框，确认后立即从内存状态和持久化文件移除。
- 空列表显示说明文案：“还没有自动跳过标记，可在播放页记录时间段”。

### 6.3 管理页播放

点击某条记录的播放按钮：

1. 通过 `audioKey` 在当前 `LibraryState.items` 中解析真实 `AudioItem`；
2. 如果存在，复用现有播放入口开始播放该音频，并返回播放页或切换到播放页；
3. 播放从 0:00 开始，不使用该音频之前保存的播放位置，以便用户验证自动跳过效果；
4. 如果多个标记属于同一音频，每条记录的播放按钮行为一致，均从 0:00 播放该音频，自动跳过所有属于该音频的标记。

找不到对应 `AudioItem` 时不应尝试播放；正常情况下该记录已在扫描同步时被清理，管理页只需做好空安全处理。

## 7. 音频删除与标记同步

自动跳过记录的生命周期跟随音频路径：

- 文件夹扫描完成后，用扫描后的完整 `AudioItem.key` 集合清理该文件夹中已经不存在的音频标记。
- 移除整个音乐文件夹时，删除其下所有音频对应的标记。
- 应用启动时，在媒体库缓存和自动跳过记录都加载后执行一次全量 reconcile，删除不再存在于媒体库的标记。
- 文件被移动、重命名或重新授权后导致 URI 改变时，视为新音频；旧标记不迁移。这符合“按路径区分”的要求，也避免误匹配同名文件。

清理操作必须同时更新 `StateFlow` 和 JSON 文件，避免 UI 已消失但下次启动又恢复。

## 8. 事件、状态和页面改动建议

建议新增：

```text
AppScreen.AUTO_SKIP_SETTINGS

AppEvent.StartAutoSkipMark
AppEvent.FinishAutoSkipMark
AppEvent.OpenAutoSkipSettings
AppEvent.DeleteAutoSkipSegment(id)
AppEvent.PlayAutoSkipAudio(audioKey)
```

也可以将打开/播放/删除统一保留在 `AppEvent` 中，将开始/结束标记作为明确的两个事件，避免 UI 层直接操作仓库。

`AppUiState` 增加：

```text
autoSkipSegments: List<AutoSkipSegment>
activeAutoSkipMark: ActiveMark?
```

## 9. “列表”入口的处理范围

根据已确认的范围，移除独立的列表按钮，将列表入口和循环方式统一放入播放模式菜单，不改变现有播放逻辑：

- 删除播放页独立的“列表”按钮。
- 保留 `AppDialog.Queue` 和队列列表小窗 UI，并从播放模式菜单打开。
- 保留 `PlaybackState.queue`、`currentIndex`、`QueueNavigator`、`PlayQueue`、`JumpToItem`。
- 播放模式菜单中的“循环方式”继续打开小窗，在小窗中更新现有 `SetPlayMode` 命令。
- 保留上一曲/下一曲、封面左右滑动、播放模式菜单、循环方式小窗，以及顺序/单曲循环/列表循环/随机播放相关状态和设置。
- 管理页点击某条标记的播放按钮时，复用现有 `AppViewModel.playAudio`/队列播放入口，选中的音频从 0:00 开始，之后继续遵循当前队列和播放模式逻辑。

因此，播放页底部操作区仍保留三个操作：播放模式菜单、定时和跳过标记；播放模式菜单内依次提供播放列表和循环方式。

## 10. 验收标准

- 当前无音频时，跳过标记按钮不可用。
- 点击一次变为“结束标记”，点击第二次能保存一个有效区间并恢复按钮。
- 同一音频连续保存多个区间，管理页均能显示。
- 不同路径但标题相同的音频，标记互不影响。
- 播放进入区间后自动跳到结束位置，区间外播放不受影响。
- 播放页菜单可分别输入开头和结尾的秒数，并作用于当前音频所在目录的所有音频。
- 目录级规则单独保存，不生成普通自动跳过记录，也不进入设置页自动跳过管理列表；输入 0 可分别关闭开头或结尾规则。
- 重叠/相邻区间不会在区间边界反复跳转。
- 管理页按最后修改时间倒序显示，可播放、可删除、不可编辑。
- 删除音频或移除所属文件夹后，对应标记不再出现，重启应用后也不会恢复。
- 播放/暂停、上一曲/下一曲、快进/快退、播放模式、队列播放、定时暂停和自动跳过行为正确；仅播放页独立列表按钮被移除，列表小窗仍可从菜单打开。

## 11. 当前已确认的产品决策

- 管理页按最后修改时间倒序显示，最新修改的标记排在最上面。当前版本不提供编辑操作，因此新建记录时的时间同时作为最后修改时间。
- 管理页播放从 0:00 开始，并沿用现有队列和播放模式逻辑。
- 只删除播放页独立的列表入口，列表小窗、内部播放队列及相关逻辑全部保留，并通过播放模式菜单访问。
- 结束位置不晚于起点时不保存，并继续保持“结束标记”状态。
- 自动跳过允许约 500ms 的响应误差。
- 开头/结尾规则按秒输入，以当前音频的 `folderUri + relativePath` 区分目录，单独持久化且不纳入普通标记管理页。
